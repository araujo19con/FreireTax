## Naming Conventions

**Files:**

- Page components: PascalCase, single word or compound — `Empresas.tsx`, `AnaliseRFB.tsx`, `MinhaSemana.tsx`
- Sub-page components: PascalCase with domain prefix — `EmpresasTableView.tsx`, `AcaoEmpresasPanel.tsx`
- Hooks: camelCase with `use` prefix — `useEmpresas.ts`, `useBulkEnrich.ts`
- Lib utilities: camelCase — `format.ts`, `cnpj.ts`, `supabaseFetchAll.ts`
- Tests: `<module>.test.ts` co-located in `src/lib/` — `cnpj.test.ts`, `criterios.test.ts`

**Components:**

- PascalCase function components with named export (not default) for shared components: `export function EmpresaDialog()`
- Default export for page components: `export default function Empresas()`

**Hooks:**

- `use` prefix, camelCase: `useAuth`, `useEmpresas`, `useBulkEnrich`
- Mutation hooks exported as separate named functions: `useCreateEmpresa`, `useUpdateEmpresa`, `useDeleteEmpresa`

**Types/Interfaces:**

- PascalCase interfaces: `Empresa`, `EmpresaFilters`, `EmpresaSort`, `AuthContextValue`
- DB row types sourced from autogenerated types: `Database["public"]["Tables"]["empresas"]["Row"]`

## Module Boundaries

**Pages (`src/pages/`):**

- Own their route-level state (`useState`, `useSearchParams`)
- Compose domain hooks + shared components
- May define local interfaces for API response shapes
- Sub-directories contain components that are NOT shared across pages

**Components (`src/components/`):**

- Reusable across two or more pages
- May own their own data fetching (dialogs load their own relations)
- Never import from `src/pages/`

**Hooks (`src/hooks/`):**

- Single domain per file
- Export named functions for each operation (query + each mutation separately)
- Always invalidate relevant query keys after mutations
- `useAuth` is the only hook that uses React context; all others use TanStack Query

**Lib (`src/lib/`):**

- Pure functions — no React, no hooks, no Supabase client (except `supabaseFetchAll.ts` and `audit.ts` which import the client)
- Domain utilities that belong to one concern: `cnpj.ts`, `format.ts`, `criterios.ts`
- Test files live here co-located: `cnpj.test.ts`, `criterios.test.ts`, `proposta.test.ts`

**Integrations (`src/integrations/supabase/`):**

- `client.ts` — import and re-export the Supabase client; nothing else
- `types.ts` — autogenerated; never hand-edit; grep for specific types rather than reading whole file

**shadcn/ui (`src/components/ui/`):**

- Do not edit. Compose on top. The only exception is when a shadcn primitive needs an explicit a11y fix requested by the user.
