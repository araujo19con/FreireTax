# Testing

**Analysis Date:** 2026-05-29

## Test Setup

**Framework:** Vitest

- Config: `vitest.config.ts` at project root
- Uses `@vitejs/plugin-react-swc` (same SWC-based React plugin as production build)
- DOM environment: `jsdom` (`test.environment: "jsdom"`)
- Globals mode: `true` — `describe`, `it`, `expect`, `vi` are available without importing
  - Backed by `tsconfig.app.json`: `"types": ["vitest/globals"]`
- Path alias: `@/` → `src/` (mirrors production config)

**Setup file:** `src/test/setup.ts`

- Imports `@testing-library/jest-dom` (extends matchers with `toBeInTheDocument`, `toHaveTextContent`, etc.)
- Stubs `window.matchMedia` (required by Radix/shadcn components that check media queries)

**Coverage:**

- Provider: `v8` (`@vitest/coverage-v8`)
- Reporters: `text`, `html`, `json-summary`
- Output: `./coverage/`
- Includes: `src/**/*.{ts,tsx}`
- Excluded from coverage: test files themselves, `src/test/**`, `src/**/*.d.ts`, `src/components/ui/**` (shadcn primitives — not authored code), `src/integrations/supabase/types.ts` (autogenerated), `src/main.tsx`, `src/vite-env.d.ts`

**Run Commands:**

```bash
bun test                   # run all tests (vitest run)
bun test --watch           # watch mode
bun test --coverage        # with coverage report
```

## Test File Organization

**Location pattern:** Test files are co-located in `src/lib/` alongside the module they test.

- `src/lib/cnpj.ts` → `src/lib/cnpj.test.ts`
- `src/lib/criterios.ts` → `src/lib/criterios.test.ts`
- `src/lib/proposta.ts` → `src/lib/proposta.test.ts`
- `src/lib/supabaseFetchAll.ts` → `src/lib/supabaseFetchAll.test.ts`
- `src/test/example.test.ts` — placeholder/smoke test (trivial `expect(true).toBe(true)`)

**Naming:** `<module-name>.test.ts` — matches the source file name exactly.

**Vitest include glob:** `src/**/*.{test,spec}.{ts,tsx}` — picks up co-located tests anywhere in `src/`.

## Test Patterns

**Suite structure:**

```typescript
import { describe, it, expect } from "vitest"; // explicit imports used even with globals
import { functionUnderTest } from "./module";

describe("functionName", () => {
  it("describes the behavior in Portuguese", () => {
    expect(functionUnderTest(input)).toBe(expected);
  });
});
```

**Description language:** Test descriptions are written in **Portuguese** (matching the project's language convention).

- `it("remove formatação", ...)` — `cnpj.test.ts`
- `it("aceita CNPJs válidos conhecidos", ...)` — `cnpj.test.ts`
- `it("não dispara quando resposta undefined", ...)` — `criterios.test.ts`

**Multiple `describe` blocks per file:** Each exported function gets its own `describe` block.

**Mocking with `vi`:**

- Used in `supabaseFetchAll.test.ts` to mock the Supabase query builder
- Pattern: `vi.fn().mockResolvedValue(...)` for single-call mocks
- Pattern: `vi.fn().mockResolvedValueOnce(...).mockResolvedValueOnce(...)` for sequential calls
- `vi.fn().mockImplementation(...)` for permanent behavior (e.g., infinite page loop in safety cap test)

```typescript
// Example from supabaseFetchAll.test.ts
const builder = vi.fn().mockResolvedValue({ data: [], error: null });
const out = await fetchAllRows<{ id: number }>(builder, { pageSize: 100 });
expect(builder).toHaveBeenCalledWith(0, 99);
```

**Async tests:** Use `async/await` directly in `it()` callbacks. `fetchAllRows` tests use `await expect(...).rejects.toBe(err)` for rejection assertions.

**Fixtures / test data:** Inline constants at the top of test files — no shared fixture files.

```typescript
// Example from proposta.test.ts
const baseCtx: ProposalContext = {
  empresa: { nome: "Acme S.A.", cnpj: "11.222.333/0001-81" },
  contato: { nome: "Maria Silva", cargo: "CFO", email: "m@acme.com" },
  acao: { nome: "Rescisória Tema 985" },
  // ...
};
```

**XSS/security testing:** `proposta.test.ts` includes XSS escape tests for `renderVariaveis` and HTML sanitization via `sanitizeProposalHtml`. Pattern: inject `<script>`, `onclick=`, `javascript:` payloads and assert they are stripped.

**Locale-resilient assertions:** When testing `Intl.NumberFormat` output (BRL formatting), tests use `.toMatch(/^R\$\s10\.000,00$/)` with `\s` instead of a literal non-breaking space (`U+00A0`) to be resilient across environments.

## Test Coverage

**Well-tested (pure utility functions in `src/lib/`):**

- CNPJ formatting and validation logic
- Eligibility rule evaluation (`respostaDisparaExclusao`)
- Proposal template rendering and HTML sanitization
- Supabase pagination utility

**Not tested (no test files exist):**

- All React components (`src/components/`) — zero component tests
- All pages (`src/pages/`) — zero page tests
- All hooks (`src/hooks/`) — `useEmpresas`, `useAuth`, `useCriterios`, etc. have no tests
- `src/lib/format.ts` — `formatCurrency`, `formatDate`, `formatRelativeDate` have no dedicated tests
- `src/lib/regimeTributario.ts` — `getRegimeEffective`, `humanizeRegime`, `regimeColor` untested
- `src/lib/errors.ts` — `extractErrorMessage`, `extractPgErrorCode`, `isUniqueViolation` untested
- `src/lib/empresaFiltersInMemory.ts` — in-memory filter logic untested
- `src/lib/prospeccaoStatus.ts` — status transition logic untested
- `src/lib/exportEmpresasAcao.ts` — export generation untested
- Supabase integration (edge functions, RPC calls) — not unit-tested by design

## Gaps

**High priority to add:**

- `src/lib/format.ts` — straightforward pure functions, easy to test, used everywhere
- `src/lib/regimeTributario.ts` — `getRegimeEffective` has branching logic worth covering
- `src/lib/errors.ts` — `extractErrorMessage` handles multiple error shapes; test each branch

**Medium priority:**

- `src/lib/empresaFiltersInMemory.ts` — in-memory filter engine for client-side filtering; untested branching
- `src/lib/prospeccaoStatus.ts` — status transition table affects business logic

**Low priority / not feasible without major infra:**

- React component tests require mocking Supabase client — would need `vi.mock("@/integrations/supabase/client")` setup; valuable but currently no precedent in this codebase
- Hook tests require `renderHook` from `@testing-library/react` + QueryClient wrapper — package is installed as devDependency but never used
