# Code Conventions

**Analysis Date:** 2026-05-29

## Language & Style

**TypeScript:**

- `strict: false`, `noImplicitAny: false` in `tsconfig.app.json` — the project is not fully strict
- `noFallthroughCasesInSwitch: true` — exhaustive switch patterns required
- Target ES2020, module resolution: `bundler`
- Path alias: `@/` maps to `src/` (both tsconfig and vitest config)

**ESLint (two-tier setup in `eslint.config.js`):**

- Tier 1 (all `*.ts/*.tsx`): `@typescript-eslint/recommended`, `react-hooks/recommended`, `react-refresh`
  - `no-unused-vars`: `warn` (ignores `^_` prefix for args, vars, caught errors, and rest siblings)
  - `no-explicit-any`: `warn` (~117 known hits; migrate gradually)
- Tier 2 (`src/**` only — type-aware): `recommendedTypeChecked`
  - `no-floating-promises`: `warn` — catches `void supabase.from(...).update(...)` without `await`
  - `await-thenable`: `warn`
  - All `no-unsafe-*` rules: `off` — too many legacy hits; will re-enable as `any` usage decreases

**Prettier (`prettierrc.json`):**

- `semi: true`, `singleQuote: false` (double quotes), `trailingComma: "es5"`
- `tabWidth: 2`, `printWidth: 100`, `arrowParens: "always"`
- `endOfLine: "lf"`, `bracketSpacing: true`
- Plugin: `prettier-plugin-tailwindcss` (auto-sorts Tailwind class names)

## Naming Conventions

**Files:**

- React components: `PascalCase.tsx` — `EmpresaDialog.tsx`, `PageHeader.tsx`, `BuscarCNPJDialog.tsx`
- Page-level route components: `PascalCase.tsx` in `src/pages/` — `Dashboard.tsx`, `Empresas.tsx`
- Sub-route folders: lowercase — `src/pages/acoes/`, `src/pages/elegibilidade/`, `src/pages/empresas/`
- Hooks: `camelCase` starting with `use` and `.ts` (or `.tsx` if JSX) — `useAuth.tsx`, `useEmpresas.ts`
- Library/utilities: `camelCase.ts` — `format.ts`, `cnpj.ts`, `regimeTributario.ts`, `errors.ts`
- shadcn primitives: `kebab-case.tsx` in `src/components/ui/` — `alert-dialog.tsx`, `scroll-area.tsx`
- Test files: `<name>.test.ts` co-located in `src/lib/` or in `src/test/`

**Functions:**

- Utilities: camelCase — `formatCurrency`, `validateCNPJ`, `unmaskCNPJ`, `extractErrorMessage`
- Components: PascalCase named exports — `export function EmpresaDialog(...)`, `export function PageHeader(...)`
- Hooks: camelCase with `use` prefix — `useAuth`, `useEmpresas`, `useCriterios`
- React Query hook families follow `useCreateX`, `useUpdateX`, `useDeleteX`, `useBulkDeleteX` pattern
- Domain helpers may use Portuguese names — `humanizeRegime`, `defaultRegraFor`, `respostaDisparaExclusao`

**Variables:**

- Locals and params: camelCase — `empresaId`, `prospeccoes`, `fetchingRFB`
- Module-level constants: `SCREAMING_SNAKE_CASE` — `REGIMES_TRIBUTARIOS`, `ESCRITORIO_DEFAULT`, `PG_ERROR_CODES`, `MAX_ANEXO_BYTES`
- React refs: suffix with `Ref` — `reqIdRef`, `mountedRef`, `fileInputRef`
- Domain identifiers stay in Portuguese matching DB column names — `empresas`, `acoes`, `elegibilidade`, `prazo`, `assigned_to`

**Types:**

- Interfaces and type aliases: PascalCase — `EmpresaFilters`, `ProposalContext`, `RegraExcludente`, `RespostaValor`
- Union types for domain enums: string literal unions — `EmpresaStatus = "prospect" | "cliente" | "inativo"`
- DB-row types: inline interfaces in hooks (e.g., `Empresa` in `src/hooks/useEmpresas.ts`) rather than importing the autogenerated 1600-line `types.ts`

## Component Patterns

**Structure:**

- Named function exports (not `export default`) for components — `export function EmptyState(...)`
- Props typed via local `interface XxxProps` defined immediately above the component
- Destructured props in function signature
- Discriminated union props used when a prop can be one of two behaviors (e.g., `EmptyAction` in `src/components/EmptyState.tsx` with `onClick` vs `to`)

**Shared layout components (always use, never reimplent):**

- `PageHeader` — consistent page title + action area (`src/components/PageHeader.tsx`)
- `EmptyState` — guided empty state with optional `action` and `secondaryAction` (`src/components/EmptyState.tsx`)
- `LoadingState` — loading spinner placeholder (`src/components/LoadingState.tsx`)
- `EmpresaFilterPopover` + `EmpresaFilterChips` — sole filter UI for Empresas and Matriz Elegibilidade (`src/components/EmpresaFilterPopover.tsx`)

**Tailwind via `cn()`:**

- All conditional class names use `cn()` from `@/lib/utils` (shadcn's `clsx` + `twMerge` wrapper)
- Pattern: `cn("base-classes", conditional && "extra-class", className)`

**Icon usage:**

- Icons from `lucide-react`, typed as `LucideIcon`, always `aria-hidden="true"` when decorative

## State Management Patterns

**Server state:** `@tanstack/react-query` — used for all Supabase data fetches.

- Global config: `staleTime: 30_000`, `refetchOnWindowFocus: false` (in `src/main.tsx` QueryClient)
- All mutations call `queryClient.invalidateQueries({ queryKey: [...] })` on success
- Hook convention: each entity has a dedicated hook file in `src/hooks/` (e.g., `useEmpresas.ts`, `useCriterios.ts`) that exports both query hooks and mutation hooks

**Local UI state:** `useState` — for dialog open/close, form temporary values, filter panel visibility

- Never `useState` for data that comes from the server — always React Query

**Forms:** `react-hook-form` + `@hookform/resolvers/zod` — Zod schema defines validation, `useForm` manages state

## Error Handling

**PostgrestError awareness:** PostgrestError from `supabase-js` is NOT `instanceof Error`.

- Use `extractErrorMessage(err)` from `src/lib/errors.ts` to get a readable string from any unknown error
- Use `extractPgErrorCode(err)` to get the Postgres code (e.g., `"23505"` for unique violation)
- Use `isUniqueViolation(err)` to detect duplicate CNPJ errors
- Never use `err.message` directly on caught Supabase errors — it may be undefined

**Toasts:**

- `import { toast } from "sonner"` — sonner is the canonical toast library
- Do NOT use Radix/shadcn toast (`use-toast.ts` is legacy, kept for compatibility only)
- Success: `toast.success("Mensagem de sucesso")`
- Error: `toast.error(extractErrorMessage(err))`

**Error boundaries:**

- `ErrorBoundary` component at `src/components/ErrorBoundary.tsx` wraps routes in `App.tsx`

**Async in mutations:**

- ESLint warns on `no-floating-promises` — always `await` Supabase mutations or explicitly handle with `.then().catch()`

## Comments & Docs

**Language:** All comments in **Portuguese**, short, explaining _why_ (not _what_).

**JSDoc-style block comments** used at the top of utility files to describe the module's purpose (see `src/lib/errors.ts`, `src/lib/cnpj.ts`, `src/lib/format.ts`).

**Inline comments:** Used to explain non-obvious logic — constraints, workarounds, and Supabase-specific behavior. Examples from the codebase:

- `// rejeita todos os dígitos iguais` before the regex in `cnpj.ts`
- `// opcao_simples === false não permite escolher entre presumido e real` in `regimeTributario.ts`

**What does NOT get commented:** Straightforward CRUD, obvious state setters, standard React patterns.

## Anti-Patterns to Avoid

**Reimplementing shared helpers:**

- Never reimplement CNPJ mask/validation — use `maskCNPJ`, `unmaskCNPJ`, `validateCNPJ` from `src/lib/cnpj.ts`
- Never reimplement error extraction inline — use `extractErrorMessage` / `extractPgErrorCode` from `src/lib/errors.ts`
- Never reimplement formatting — use `formatCurrency`, `formatDate`, `formatRelativeDate`, `formatCNPJ` from `src/lib/format.ts`
- Never reimplement regime helpers — use `getRegimeEffective`, `humanizeRegime`, `regimeColor` from `src/lib/regimeTributario.ts`
- Never duplicate filter UI for empresas — use `EmpresaFilterPopover` + `EmpresaFilterChips`

**Known bugs that must not be reintroduced:**

- `tarefas` trigger uses `created_by`/`assigned_to`, NOT `user_id` — never add `user_id` to the trigger
- Vercel SPA: `vercel.json` must include `/(.*) → /index.html` rewrite — do not remove it
- BrasilAPI: rate limit requires 350ms delay + retry on 429 — never batch without delay
- Every `prospeccao` needs both `empresa_id` and `acao_id` — `elegibilidade_id` is legacy linking
- Print PDF: use `<table>` with `<thead>`/`<tfoot>` for repeating headers, never `position: fixed`
- Import CSV: use `findColumnExact` for "status" column to avoid false positive with "situação"
- `rfb_estabelecimentos_busca`: must be populated via `tools/import-rfb-slim.mjs` before name-based CNPJ search works

**Emoji:** No emoji in code files or documents unless the user explicitly requests it.

**UI language:** All UI text (labels, messages, toasts, placeholders) must be in **Portuguese**.

**Reading types.ts:** Never read `src/integrations/supabase/types.ts` fully — 1,624 lines autogenerated. Use Grep for specific types.
